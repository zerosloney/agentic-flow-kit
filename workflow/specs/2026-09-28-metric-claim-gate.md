# SPEC — 量化断言指标签名机器门（check-loop 检查 16）

## 功能行为

把 `2026-09-28-claim-exceeds-fix` 立下的「量化断言单源」纪律从**人工遵守**升级为**机器门**。

### 用户场景

1. **作者写断言**：在活跃态文档（draft/approved/open）里引用已登记指标时，写**签名** `\{{指标名}}`（小写点分）而非手敲数字——如「本仓台账共 \{{ledger.lines}} 行」。
2. **门禁抓未回填**：`check-loop` 报 `[WARN 指标待回填] <文件>:<行> \{{ledger.lines}} 实时值 = 79——请把签名替换为该数字`。作者据此填实（**工具给出实时值，不需自己数**）。
3. **门禁抓未登记**：写了 `\{{foo.bar}}` 但登记表无此项 → `[WARN 指标未登记]`（未登记＝无从对账，不静默放过）。
4. **门禁抓「登记了却没查」**：登记表加了一行但 `derivers` 无实现 → `[WARN 指标登记] 指标「X」无对应取数器`——防「登记表看起来在管、其实没实现」的假阴性。

> **转义约定（本 spec 自带）**：文档中**讲语法 / 举例 / 引用告警原文**时，签名前须加反斜杠（`\{{…}}`）表示「此处是示意、非断言」——否则检查 16 会把「文档在教怎么用签名」误判为「作者忘了回填」（本检查实现后**立刻在自己的文档上抓到该需求**，见风险评估）。选显式转义而非「同句含『如/例』即豁免」的启发式：后者会按措辞松紧漂移，作者能无意触发豁免而漏过真断言。

### 核心设计决定：只查显式签名，不全文扫数字

**据实说明（这是本 spec 最关键的一条，非偷懒）**：本仓活跃文档中「N 行 / N 条 / N 份」类表述有 **65 处**（实测），其中绝大多数是**历史叙述**——描述某次提交当时的规模（如「47 文件，2214 行」），这类数字**天然不会随当前事实变化**，是正确的。

全文扫描会对这些正确表述产生**大量假阳性**，而 `check-loop.mjs` 已把红线立死：

> 无判定依据的行不产出不可消除噪声（沿 2026-09-27 audit-gate-hardening P3：噪声淹没真漏点）

同一红线上一轮已经用血换过一次（旧并录判据不按日期门豁免，退役前本仓 22 条 advisory 中 14 条为该告警，不可消退）。**故本检查假阳性恒 0，代价是覆盖面依赖作者登记**——这是自觉的取舍，不是能力缺口。

### 边界与异常

| 情形 | 行为 |
|---|---|
| 登记表 `.agents/metric-claims.txt` 不存在 | **静默跳过**（未启用该检查的装户不应被噪声打扰） |
| 文档无任何签名 | 零告警（**假阳性恒 0** 的核心保证） |
| 装户模板占位符（全大写 SCREAMING_CASE，如构建命令 / 看板端口 / 项目名） | **不误报**——签名形态收窄为小写点分 `\{{a.b}}`；实测不收窄会对本仓 plans 内 11 处合法模板占位符全部误报 |
| 终态文档（done/fixed/closed/superseded/cancelled）含签名 | **不扫**（沿检查 4 现有尺度：历史数字是历史叙述） |
| 登记表行格式非法 / 登记名与取数表达式不一致 | 出账 `[WARN 指标登记]`（fail-loud，不静默） |
| 文档**讲语法 / 举例 / 引用告警原文**（非真断言） | 签名前加反斜杠转义（`\{{…}}`）→ 该行不作签名扫描（见下「转义约定」） |
| 指标取数依赖网络 / 非确定性 | **设计禁止**——`derivers` 为闭集，全部本地确定性（台账计数 / 文档计数） |

### 转义约定（实现期发现：本检查在自己的文档上抓到的需求）

本检查实现完成后**立刻在本仓报出 5 处告警**——全部来自**本 spec 与 README 自身**：它们在「讲语法 / 举例 / 引用告警原文」，却被判为「作者忘了回填」。

**解决**：签名前加反斜杠（`\{{…}}`）表示「此处是示意、非断言」，该行整体退出签名扫描。

**为什么用显式转义而非启发式豁免**（如「同句含『如 / 例 / 签名』等标记词即豁免」）：启发式会**按措辞松紧漂移**——作者换个说法就漏判，甚至无意中触发豁免而让真断言过关。显式转义零歧义，且漏写转义的代价只是「多一条提示」，不会放过真问题。

### 为什么检查 16 必须有「可加载」守卫用例（实现期教训）

实现期把 `continue` 误用在 `forEach` 回调内 → 模块 **SyntaxError → check-loop 整体崩溃退出**。危险的是：当时输出里「指标告警 0 条」**看起来像通过**，实际是脚本根本没跑起来。**假绿比红更危险**——一条语法错能让全部门禁静默失效而不被察觉。

故 T3 增设守卫用例（「check-loop 可正常加载运行」），变异自验证实：注入该语法错 → **全部 90 个用例一起变红**（而非静默全绿），门禁失效必然可见。

## 数据流

```
.agents/metric-claims.txt（单源登记表：指标名 = 取数表达式）
        │
        │ 读（缺失则整段跳过）
        ▼
check-loop 检查 16
        │
        ├─ 解析登记表 → declared 集合（非法行 / 名不一致 / 无取数器 → WARN 登记）
        │
        ├─ 扫活跃态文档（workflow/{intents,specs,plans,incidents} 中 draft/approved/open
        │   + workflow 根级 *.md），逐行匹配 /\{\{([a-z][a-z0-9]*(?:\.[a-z0-9]+)+)\}\}/g
        │
        └─ 每个签名：
             ├─ 未登记 → WARN 指标未登记
             └─ 已登记 → 调 derivers[name]() 实时取数 → WARN 指标待回填（附实时值）

derivers（闭集，全部本地确定性、零网络）：
  ledger.lines              台账非空行数
  ledger.linesWithBatch     台账含 "batch" 行数
  ledger.linesWithoutBatch  台账不含 "batch" 行数（schema 演进前历史行）
  docs.count.{intents,specs,plans,incidents,all}  workflow/<sub> 文档份数（排除 _TEMPLATE.md）
```

**不登记 advisory 总数类指标**：它由 `check-loop` 自身产出（检查 16 是其一部分），自引用会让「报告本身改变被报告的数」，产生不可稳定对账的循环。

## 约束遵守映射

- **双源纪律**：引擎与登记表改动一律改 `templates/`（或 `templates/_agents/`），随后 `flow-kit sync` 刷装副本 + kit.json 台账 sha；`source-sync-check --diff` 须 0 差异——T1/T2/T4/T6 遵守
- **占位符残留纪律**（`doctor` §5）：本检查自身的**注释与代码**不得含字面 `\{{全大写}}` 形态（会被 §5 判为占位符残留）——实现期已实测踩中（注释里写「`{{BUILD_CMD}}` 类」被判残留），改述为文字描述；`metric-claims.txt` 正文亦只用 `{{指标名}}` 小写点分形态
- **检查项编号不增删改号**：新增第 **16** 项（不改既有 1-15 判据）；`gate-checklist` PAIRS **必须同步登记**，否则工具报「未登记」
- **噪声红线**：假阳性恒 0 是本 spec 的**首要验收判据**（无签名零告警 + 全大写不误报两条用例钉死）；任何「顺手扩到全文数字扫描」的改动都违反 P3 教训
- **fail-loud 纪律**：未登记 / 无取数器**必须出账**——静默会让「登记表看起来在管、其实没查」这种假阴性不可见（沿本仓 enum 单源缺失 fail-loud 的既有取向）
- **常驻面预算**：改动集不含 AGENTS.md / commands（`workflow/README.md` 为 owned 且不在预算表），不触预算
- **`--no-verify` 禁令**：门禁被拦时按提示修完原路重试
- **提交约定**：spec / plan 随代码同一提交；确认后立即 `docs(workflow)` 单独提交留痕
- **存量不误伤**：终态文档不扫、无签名不报——本仓实跑 advisory 数**改前改后须一致**（复核须独立复现）

## 风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| **扩到全文数字扫描 → 不可消退噪声**（违 P3 红线） | **高** | 本 spec 把「只查显式签名」写为**核心设计决定**并附实测依据（65 处数字断言多为历史叙述）；两条假阳性用例（无签名 / 全大写）钉死；复核须独立扫本仓确认零误报 |
| 覆盖面依赖作者登记——不登记就查不到 | 中 | **自觉的取舍**（据实声明，不宣称「已覆盖全部量化断言」）：假阳性恒 0 的代价就是覆盖面有界。故 README 纪律节如实写「签名是可选强化手段，不是强制」；后续若要扩大覆盖面，走「提高登记率」而非「放宽匹配」 |
| 头注释格式不符致 `gate-checklist` 报「断档」 | 中 | 实测踩过（首版行首多一个空格 + 括号写在 severity 位 → 解析不到）。判据写进 spec 系统改动表：行首 `// 16. 标题 [warning]`；T4 验收含 `gate-checklist --diff` 0 断档 / 0 未登记 |
| 检查自身注释含 `\{{全大写}}` 被判占位符残留 | 中 | 实测踩过（`doctor` §5 报残留）。已在「约束遵守映射」立为纪律条目；T6 验收含 `doctor` 0 WARN |
| 新增一次全目录扫描拖慢 check-loop | 低 | 仅在登记表存在时执行；扫描面为活跃态文档（本仓约 20 份）而非全量 139 份；纯本地计数，无进程 fork、无网络 |
| 取数器与登记表不同步（加了指标忘了实现） | 中 | fail-loud 出账「无对应取数器」+ 专用用例；这是「登记了却没查」的唯一可机器捕获点 |
| 自引用导致不可稳定对账 | 低 | 明确**不登记** advisory 总数类指标（检查自身的输出），已在数据流节写明理由 |
| 回滚难度 | 低 | 单文件新增检查段 + 新登记表 + 测试 + 一处文档；`git revert` 单提交即回；无数据迁移、无 schema 变更 |
