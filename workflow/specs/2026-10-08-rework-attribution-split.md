# SPEC — rework-attribution-split

对应入口：../intents/2026-10-08-rework-attribution-split.md

## 功能行为

**场景 A · 行内双值解析（新）**：`parseResult('返工×1 + 门禁噪声×1')` → `{ kind: 'rework-mixed', rework: 1, reworkNoise: 1 }`。判据须区分「纯设计」「纯噪声」「混合」三态，并让 `metrics()` 分别累加两个分量。**混合态的 `kind` 不得计入 pass/fallback/pending/unknown 任何一档**（否则 `total` 分母被污染）。

**场景 B · 任务总数不虚增**：一行仍是一个任务。`返工×1 + 门禁噪声×1` 的行 `total` 计 1、`passRate` 分母计 1——**不因行内有两个数字就拆成两个任务**。这是本单与「拆成两行」方案的根本区别：后者会虚增有效任务数、进而抬高一次通过率分母。

**场景 C · 旧三格式逐条不变**：`一次通过` / `返工×N` / `返工×N（门禁噪声）` / `主兜底` / `返工待修` 的解析与判定行为**逐字节不变**（既有测试断言零改动即钉子）。`kind` 字段的既有取值域不新增对外语义——`rework-mixed` 是新增内部态，只在 `metrics()` 里分流，不影响 `total`/`pending`/`unknown` 的既有计算。

**场景 D · 回溯标注（只标能逐点对质者）**：`delegations.md` 中 **L29 `adopter-ci-github`** 的结果列由 `返工×2` 改为 `返工×1 + 门禁噪声×1`，备注列写明：① 规则面预算拦 AGENTS.md 7969B>7680 标为噪声（新增 CI 口径行属合法增长，预算上限系历史实测值）；② rule-budgets 只改装副本属真实双源违约，保持设计返工。其余 28 行**不改结果列**。

**场景 E · 判定留痕（不标也要留痕）**：在 `delegations.md` 增设判定留痕节，记录 29 行的逐行结论——可标 / 不可标 / 不可精确拆分及原因。**「没标」必须有据可查**，否则下一个人会重复做同样的逐行审计。

**边界与异常**：格式含非法数字（`返工×a`）→ 落 `unknown`（记录本身有问题，单列不混进待修）；只有噪声分量而无设计分量（`返工×0 + 门禁噪声×2`）→ 允许但等价于纯噪声档；空格变体（`返工×1+门禁噪声×1` 无空格）→ 宽容解析。

## 数据流

- 解析：`delegations.md` 两表 → `splitTables` → `readLedger` → `parseResult(raw)` 返回 `{kind, rework, reworkNoise}` → `metrics()` 累加 `reworkSum`（设计）与 `reworkNoiseSum`（噪声），`total` 按 kind 有效性计 1。
- 消费：`gateMonth` 第 3 项读 `reworkSum` 判 `=0`、`reworkNoiseSum` 进描述；`expansionVerdict` 不变；`gen-workflow-dashboard.mjs` 的 `qualityRows` 复用同一 `metrics()`，新增列「门禁噪声返工」已在本仓 1.3.0+ 存在，无需再改。
- 回溯：人工逐行判定 → 结果列改写 + 备注列补依据 → 台账结构不变（仍一行一任务）→ 聚合重算。
