# 回归清单（活文档）

> 用途：deploy 清单「回归必过」与 incidents 复盘「防复发验证」的统一落点。
> 本清单是**活文档**：随模块上线补充、随 incident 追加、随功能演进修订；代码演进后以本清单与实际行为为准。
> **引用一致性**（关单活文档门）：条目引用的仓库相对路径（代码/证据文件）与 `workflow/**.md` 文档须仍存在——提交时 check-loop 检查 27 出 WARN，关单（done/closed）时被 confirm-doc 拒绝落账（判定单源 `check-regression-consistency.mjs`，弱档存在性；tmp/ 等 gitignore 易失前缀只提示不拦）。

## 维护规则

1. **deploy 前**：过本清单中「涉及模块」的全部条目 + 跑自动化测试（项目防复发用例）
2. **incident 后**：防复发条目追加到「防复发验证」节，不留在 incident 文档里；能自动化的落测试用例
3. **模块上线/走查后**：为该模块补关键路径条目
4. 条目过时（功能下线/行为变更）时删除或改写，不保留失效条目
5. **新增防复发条目落点优先级**：自动化用例 > 脚本化断言 > 人工步骤（仅剩视觉/交互断言无法脚本化时）
6. **分片（2026-10-13 ledger-shard-ledgers）**：「防复发验证」节的数据行按月存 `workflow/regression-checklist.d/<YYYY-MM>.md`（该节是唯一 append-only 追加区；上方模块节为稳定参考内容，留守本文件）。追加一行用 `node .agents/scripts/ledger-shards.mjs --append regression-checklist --row "<行>"`；读侧自动合并主台账 ∪ 全部分片。
7. **规则-执法者配对**：「防复发验证」行须在「执法者」列指认**复发时谁会红**（自动化用例名 / 钩子 / 门禁 §N / 冒烟脚本 / verify-ui 实测证据路径）——与「落点」分工：落点记修复资产在哪，执法者记什么在拦复发。无执法资产的条目在该列标 `[prompt-only]` 并于 `workflow/papercuts.d/` 当月片挂债（规则已写但没有任何东西执法 = 重犯信号）；存量行不回填，随触碰补配对。条目级退役：执法资产退役或错误已不可能再发生（功能下线/口径换代）时，条目随规则 4 删除。
