# INTENT — board-kb-p1

## 背景与问题

看板量化层与 kb 检索层能力审查（independent-reviewer，静态核对 + 受控探活/破坏性验证实测）各判 P1，用户拍板按「看板 + kb 一批 L2」收口：

1. **看板 P1-3 单包崩溃**：`new URL(req.url, …)` 位于 try 块外（workflow-board-server.mjs:210），单个畸形请求行（如 `GET http://[ HTTP/1.1`）抛 ERR_INVALID_URL 逸出 listener → 看板进程死亡，无自动重启（实测复现）。
2. **看板 P1-2 告警与 check-loop hard-block 脱钩**：回路断档 / 验收未对账 / 确认未对账 / 确认内容漂移四类 hard-block 在看板告警规则里无对应项（check 8/15 相继加入 hard 集而看板未跟）；test.md「双跑断言 hard-block 集被看板覆盖」现为必失败且无回归网；parseAcceptance 节匹配 `^## 验收标准` 与 check-loop `/^\s*##\s+[^#]*验收标准/` 口径不一。
3. **看板 P1-1 扩容门三分叉**：agg-delegations.cjs 判定「单月、平均返工≤0.3、主兜底≤10%」；workflow/delegations.md §并发扩容门槛声明「连续两个月、一次完成率≥90%、月度返工次数为 0、无主兜底信号」——脚本宽松于声明，依赖脚本 verdict 决策扩并发会放大并发（头部自注「两处须同步」已失同步）。
4. **kb P1-1 结构损坏缓存崩溃**：缓存条目 JSON 合法但 `lines` 非数组（schema 坏）时 reviveLines 直接 `.map` 抛 TypeError exit 1——违背头注释「任何读写异常静默回退全扫」与「退出码 0/1」两处声明契约（实测复现）；根因同条：CFG_FP 口径指纹漏哈希 schema 定义者 serializeLines/reviveLines，WIKI_EXTS 被手抄摘要替代——schema 演进时旧缓存按旧结构复活。

## 目标

- 看板进程对任意畸形请求不崩（400 响应）；Host 校验拒 DNS rebinding
- 看板 hard-block 告警与 check-loop 永不分叉（同一脚本同一进程输出），双跑断言可机器验证
- 扩容门判定与 delegations.md 声明一致（连续两个月 / 返工 0 / 无主兜底；doc 为权威）
- kb 缓存任何 schema 形状损坏都静默回退全扫，指纹覆盖 schema 定义者

## 非目标

- 不收看板 P2-2 marked XSS（DOMPurify 引入另议）、P2-4 ensure-board ours 复验、wiki 生成器 P2×5
- 不收宿主模块 P1×3（dotnet-ca BRE / trae deny 绕过 / CONTROLLERS_DIR——下一批 L1）
- 不改 check-loop 判定本体（看板侧只消费其输出）
- 不动扩容门样本类门槛（minSample 20 / 委派样本≥5 为统计可信度护栏，非口径分叉项，保留并注明）
