# INTENT — p2-batch1

## 背景与问题

P2 池约 26 条，用户拍板两批切法：批一收「init 装户安全 + sha 归一」主题（5 项），批二（后续）收看板/wiki/宿主面。批一五项：

1. **--force 重装静默摧毁 owned 内容**（init 审查 P2-1，批内唯一可能丢用户数据的项）：renderTree force 语义覆盖一切同名文件（含 AGENTS.md 用户自定义「项目适配区」命令、local-pre-commit 的 add-gate 接线），实测自定义行丢失且不可检测；换 --hosts 组合时旧宿主目录文件脱账成静默孤儿。
2. **发布面 EOL 卫生缺口**（P2-2）：根 .gitattributes 缺 `templates/_agents/hooks/local-pre-commit` 的 eol=lf 规则（无扩展名文件，autocrlf=true 工作树检出为 CRLF，实测 CR=6）；npm pack 不做 EOL 归一——从此工作树发布会把 CRLF 钩子投递给装户（Linux dash 下预期 fail-closed 拦死首次提交）。装户侧模板自己的 .gitattributes 反而声明了该规则（init 审查实测对照）。
3. **--board-port 值未校验**（P2-3）：任意字符串直进 vars 渲染进 AGENTS.md / workflow/README.md（AI 每会话必读面）；残余风险为注入文本污染 agent 上下文。
4. **init 输出顺序与退出码语义混乱**（P2-4）：init「安装完成」横幅先出、doctor 报告后出（doctor 结果打印在 portInUse 异步回调里）；脚本化消费方无法据输出定位问题。
5. **managed sha CRLF 跨机漂移**（papercuts 2026-09-27 立项）：经 Edit 工具改动的模板件盘面 CRLF，克隆检出 LF → doctor §4 报 13 份 WARN；closing-coverage 已修 owned 侧与 render 写盘侧，但 sync 比较对「盘面 CRLF 件 vs 台账旧 CRLF sha」的历史台账仍可能 WARN——本批把 sync 自愈路径与 doctor §4 判定彻底收口（详见 spec：实际代码面在 closing-coverage 已闭合，本批做「验证 + 台账刷齐 + 残余面确认」，避免重复改码）。

## 目标

- --force 重装不再丢失 owned 用户内容（.bak 落底 + 清单提示 + owned 例外跳过语义二选一，spec 定稿）
- 从本仓任何 EOL 形态的工作树发布，tarball 内关键脚本零 CR 字节（发布前机器断言）
- --board-port 非 1-65535 整数即拒绝
- init 退出码语义在输出中明示
- managed 台账全量刷齐为 LF 归一 sha，克隆 doctor 0 managed WARN 长效保持（回归网）

## 非目标

- 批二内容（看板 XSS / ensure-board 竞态 / wiki P2×5 / 宿主 P2×3）
- kb parseDoc 边角与 title 死负载（放弃，声明留痕）
- 不改 --force 对 managed 文件的覆盖语义（那是「重装修复」的本意；只保护 owned 面）
- 不动 sync 三态判定逻辑（managed sha 归一已在 closing-coverage 完成，本批验证 + 补漏）

## 约束

- owned 保护方案不得破坏「--force 是重装修复出口」的可用性（.bak 方案）
- .gitattributes 属仓库自有件；prepack 改 package.json（同为自有件）
- managed sha 残余面以实测为准：克隆 doctor 0 WARN 即达标，不预设立项改码
- 引擎改动经 src/ 直改；测试先行
