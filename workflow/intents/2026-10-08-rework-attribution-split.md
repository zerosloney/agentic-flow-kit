# INTENT — rework-attribution-split

## 背景与问题

`2026-10-08-selfmeasure-and-modularize` 落地了台账「门禁噪声返工」档（结果列新增 `返工×N（门禁噪声）`，扩容门第 3 项只对设计返工判 0）。用户随后指示「回溯标注存量」，实测**该档在存量数据上几乎无法应用**：

2026-10-08 逐条审 `workflow/delegations.md` 全部 **29 行含返工记录**，按「整行全部返工点均属门禁噪声才标」的严格口径，**可标 0 行**。每行至少含一个设计面返工点（复核抓出的实现缺陷 / 漏改 / codemod 缺陷 / 测试 fixture 错误）。

最接近的两行是**混合**：

- **L29 `adopter-ci-github`（`返工×2`）**：① pre-commit 规则面预算拦 AGENTS.md 7969B>7680 = **噪声**（新增 CI 口径行属合法增长，预算上限是历史实测值，门禁拦了合规改动）；② rule-budgets 只改装副本被双源门拦 = **设计**（确实违反双源纪律，门禁正确拦下真错）。
- **L33 `backflow-loop-audit-remediation`（`返工×1`）**：① 手动双侧复制漏刷 managed 台账 = **设计**；② build.md 8386B 超单篇预算 8192 被拦 = **噪声**。但该行结果列总数（1）小于备注列出的返工点数（2+），**无法确定那 1 次记的是哪一点**。

**根因不是判据太严，是台账协议承载不了归因维度**：一行只记一个返工总数，设计返工与门禁噪声混在同一数字里，无法表达「1 次设计 + 1 次噪声」。高频门禁面摩擦（规则面预算 L29①/L33②、双源纪律 L29②/L33①）恰恰全以混合形态存在。

附带发现的数据质量问题：**多处行的结果列返工总数小于备注列出的返工点数**（L31 记 ×1 但备注列 3 点、L33 记 ×1 但备注列 2+ 点），使「精确拆分」在这些行上不可能——不是不愿标，是标不出。

## 目标

- G1 台账协议支持**一行两值**：`返工×N + 门禁噪声×M`，使混合行能精确表达归因，不整行洗白。
- G2 `agg-delegations.cjs` 解析新格式并**双列准确累计**，任务总数不变（一行仍是一个任务，不虚增有效任务数）。
- G3 旧三格式（`返工×N` / `返工×N（门禁噪声）` / `一次通过` 等）解析与判定**逐条不变**，存量行零回填压力。
- G4 回溯标注存量：只标**能逐点对质**的行（首个为 L29），不能精确拆分的行如实留痕「为何不标」。
- G5 数据质量问题（返工点数 ≠ 记录数）显式留痕，不掩盖。
