# papercut-fix 回应模板

单轮回路执行器的最终输出格式。给用户看，决定他是否放行这次改动。

---

## 模板

```markdown
papercut 回路 · 第 N 轮

**目标**：L{line} `{location}`（{date}，第 {hits} 次命中）
**结论**：{A 缺陷仍在 / B 已失效 / B2 账未销（拟修已由别的改动落地）/ B3 台账方向记反（检出态实验证伪）/ C 越界待授权}

### 改动

| 文件 | 改了什么 |
|---|---|
| `{权威文件路径}` | {一句话} |
| `workflow/papercuts.md` | 回写行标记：{`✅ 已升级修复（日期）` / `⏸ 暂缓（日期）：理由`} |

### 验证

- `papercut-debt-sensor.mjs`：debt {before} → {after}（预期 -1）
- {其他检查，如体积预算核对：通过 / 不适用}

### 台账依据

{若实际修法与「拟修」列描述不一致，在此说明「拟修」列写的什么、实际怎么做的、为什么。
 B2 结论必须写出落地提交：`由 <sha>（<日期>，<标题>）落地`。}

### 需你决定

{列出需要用户拍板的事项；没有则写「无」。典型场景：
 - 结论为 C（越界）——是否单独授权改源码/连库
 - 「拟修」列描述已过期——是否更新该列文本
 - 控制器列出的「待人工定性」条目——是否本轮顺带定性
 - 改动触及常驻面体积预算——是否接受，或改为下沉/删除被取代条目}
```

---

## 格式要求

1. **先给结论，再给细节**。用户扫第一行就要知道"修了哪条、结论是什么"。
2. **「需你决定」不许空着**。即使本轮无事，也显式写「无」——让"没有待决事项"和"忘了写"可区分。
3. **验证值给具体数字**，不要只说"验证通过"。debt 的前后值是设定点误差，必须可核。
4. **不粉饰失败**。验证门红了就写红，附命令与原始报错摘要。回路的价值在于给出可信的账，不是好看的账。
5. **不写"建议接下来…"式的空话**。要写就写具体动作 + 具体条目编号。

---

## 示例（结论 A，示意——占位符形态，非真实条目）

```markdown
papercut 回路 · 第 3 轮

**目标**：L34 `.agents/commands/test.md`（静态门清单 §2 缺一条豁免说明）（<日期>）
**结论**：A 缺陷仍在

### 改动

| 文件 | 改了什么 |
|---|---|
| `.agents/commands/test.md` | §2 补一条：跳过条件的判据以 <权威判据> 为准，不以 <表象> 为准；§常见误判 补对应条目 |
| `workflow/papercuts.md` | 回写 L34 标记：`✅ 已升级修复（YYYY-MM-DD）` |

### 验证

- `papercut-debt-sensor.mjs`：debt 16 → 15（预期 -1）
- 体积预算：`node .agents/scripts/rule-budget.mjs --staged` 通过（未触 `.agents/commands/` 上限）

### 台账依据

「拟修」列写的是「补一条 <表象> 的判定说明」。实际执行时发现症状描述的是 <相邻机制>，而 §2 真正缺的是**判据本身**（<相邻机制> 只在特定前提后需要，判据该按 <权威判据>）。两者相邻但不同，已按判据写，相邻条目并入同节。

### 需你决定

- 「拟修」列文本与实际修法有偏差（见上），是否更新该列描述以免下次复发时对不上？
- 控制器列出的「待人工定性」3 条（位置列路径已不存在）——其中 1 条指向的脚本性能问题已随某次重构解决，本轮修完后建议一并定性。要不要现在处理？
```
