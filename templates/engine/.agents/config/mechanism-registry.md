# 机制使用量台账 (Mechanism Usage Registry)

> 门禁棘轮的出口：每个门禁机制的「触发统计口径 + 退役阈值 + 状态」单源登记于此（格式人工对账，机器校验段 §22 已于 2026-10-28 随 hygiene 退役）。
> **台账的目的不是记录而是强制处置**：新增机制须登记一行；
> 机制退役当日删码 + 测试 + **删本表行**（同一提交，不留死代码不留已退役行，历史查 git）。
> 列序固定：机制 | 门禁位置 | 触发统计口径 | 退役阈值 | 最近触发 | 状态 | 处置期限。
> 段编号永不重编号（承重引用）。
> 车道：仅 hard = §1 §3x §8 §15 §23（hygiene 16 段已于 2026-10-28 引擎减重第一刀全部退役）。
> 分片（gate-metrics-shard）：判定流水月度分片 `workflow/gate-metrics.d/<YYYY-MM>.jsonl`（每月一行、多机并集），读侧本地 ∪ 分片取 max；pre-push 月检自动生成、随提交入库。
> **现状**：本表全现役。zcode Bash 槽 owner 手动启用后 CLAIMS 全 true（见「接线宣称一致性」行）；engine-tests 全量不自动跑仅手动（手动探针 = 入库的 `check-loop-rev-semantics.mjs`）；pipeline-run 保留待用、不按零使用退役（登记在 `.agents/commands/pipeline-run.md` 头注）。当日增删流水见当日 git 提交。
> **per-rule 计数口径**：judgments.jsonl 的 rule 名为剥 WARN/NOTE 前缀的归一名，级别以落账来源数组为准——判读与判定分离，标签只命名规则不改判定。
> **机制类型标记**：状态列值后追加 —— `[检出型]` 0 命中即失效，适用零命中退役；`[健康静默]` 0 命中 = 当前无问题，不适用零命中退役（退役须由覆盖面失效或被取代触发）；`[不退役主干]` 机器判据/安全/状态机主干，永不退役；`[数据面]` 非门禁遥测，按「有数据月」对账。标记在第 6 列原样书写；解析内联于 `gen-engine-map.mjs`（2026-11-08 档 3 起，retire-watch 退役后仍单一解析点）。

## 维护纪律

- **一进一出**：新增门禁机制必须同时在本表登记，并点名它替代/合并的既有机制（无替代则说明增量理由）。
- **月度对账**：每月初按「触发统计口径」列刷新计数（半自动：`node .agents/scripts/agg-delegations.mjs` + `agg-judgments.mjs` 查判定流水 `.agents/judgments.jsonl`——check-loop 每次真实运行自动落账，2026-10-11 judgment-ledger 起替代人工 grep 输出；git log 统计口径不变）；
  达到阈值的行改「待退役」并填处置期限。
- **数据面机制的「现役」≠「有数据」**：复核效果台账与评审黄金集校准属数据面机制——黄金集已首跑（见该行），复核效果台账已有跑数（reviews.d 2026-10 起）。月度对账时须区分两件事：① 资产是否存在；② 本月是否产生数据并写进留痕面（未产生 → 该月记「无跑数」，连续 6 个有数据月零记录才走退役阈值，**年轻遥测不得制造假候选**，口径同 `agg-judgments --retire-candidates`）。黄金集盲评动作与双臂/方差复跑口径见 `.agents/skills/review-method/golden-set.md` 使用方法节。
- **退役动作**：当日删除机制代码 + 其测试 + 本表该行，同一提交完成（不留死代码、不留已退役行，历史查 git）。
- **体量三闸（2026-10-31 起）**：① 总量受 `rule-budgets.txt` 预算行约束（超限 verify 硬拦）；② 单行上限 `<N>#line` 机器执法（rule-budget，超标 pre-commit 硬拦——2026-10-31 上线，替代已退役的检查 22 人工纪律）；③ 行文纪律——「最近触发」只留「建门 → 关键降档 → 当前态」，细节留 git 史。**月度对账附瘦身步**：行超 `#line` 上限 80% 即时压；runtime-env 侧同纪律（已根治条目与退役机制行随确认提交删除、本机事实入 local.md、过程细节留提交信息，见该文件 §6 头注）。
- **健康静默型不适用零命中退役**：状态列标 `[健康静默]` 的机制（如告警聚合、门禁耗时埋点等），其「0 命中」语义为「当前无问题」而非「机制失效」，**不适用**「连续 6 月 = 0 → 评估退役」判据；月度对账时仅记「无跑数」，不产生退役候选。此类机制的退役须由「覆盖面失效」或「被替代机制取代」触发，由 owner 裁决后走「退役动作」同一提交删码 + 表更新。
- **模型代际触发（2026-10-16 立）**：每个机制都是对当前模型能力边界的假设，既有退役阈值只有使用维度、缺代际维度——主力模型**代际变更**（主版本号或模型家族更换，如 GLM-4.x → 5.x；小版本/推理档变更不算）后的**下一次月度对账**按下面分组逐件重评去留，结论写各机制「最近触发」列；重评本身不改状态列（退役仍走既有阈值）。分组按届时现役行归组（立法时点所列机制部分已退役）：
  - **A · 纪律假设**（无机器检查时会跳步/声称未做之事）：观察新代际 WARN/hard 是否加速归零（是 → 走既有阈值）；**不因代际主动拆门**——判据已机器化、边际成本 ≈ 0。
  - **B · 能力边界假设**（强度绑在当前模型短板上，**须主动重评**）：体积预算（长上下文增强 → 只重定上限不拆门）、复核上下文标识、触达面判低（观察判低命中率，连续零命中走既有阈值）。证据真相核验 + 密钥扫描属信任边界/安全主干：**代际不撤门**，只重评执行成本。
  - **C · 机器判据**（纯确定性检查，代际免评）。**D · 宿主生态**（跟宿主版本走，宿主升级随 Adapter 检查顺带过）。**E · 测量自举**（数据面，代际只影响结论解释；测量结论标注代际见 delegations.md 口径注）。
- **owner-fiat 复评惯例（2026-10-21 门禁极小化第 3 批 W5 立）**：凡 owner 裁决型退役/降档（非数据阈值驱动），状态保持现役并在「处置期限」列写「复评 YYYY-MM-DD」（建议 +3 月）——复评日期到期由月度对账人工催办（retire-watch 自动催办已随 2026-11-08 档 3 退役）；维持则顺延下一复评日，恢复则 revert 对应提交并回滚本表行。首个挂号称：2026-10-21 批（密钥本地不扫 / §1 配对降档 / §3 三件套降档 / §14 留痕降档），复评 2027-01-21。已退役（删码）行不挂——恢复走重新建门。
