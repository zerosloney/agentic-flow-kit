# page-refactor — 业务模块改造（PO 样板模式）

## 定位

- **改造范围 = 整个功能模块**：列表页 + 新建 + 查看 + 编辑一起改造，不是只做布局微调。目标形态 = PO / supplier 页面现在的样子；当前形态离目标远的（如 Drawer 编辑型），走「形态跃迁」路径补齐。
- **施工权威在** `references/templates.md`（S1–S12）。本文件只留盘点、红线和验收；进入施工步再读模板，不在盘点阶段整篇加载。类名（`xx-detail`/`xx-list`）按目标页面替换，字段/按钮/动作集按目标页面业务替换，布局骨架与机制逐字保留。
- **贴合目标项目现状**：表格技术、共享组件、基建按目标项目实际情况选型（见「表格技术选型」与「基建依赖与降级表」），不强制引入新依赖。
- **溯源**：模板沉淀自本仓库采购订单（purchaseOrder）与供应商（supplier）页面改造（2026-10，本仓库 commit `e6f33915` 起系列迭代），经该系列多轮 L1 plan 全套断言实测验证。
- **样板参照（可选）**：若目标分支存在已改造的样板页（`frontend/src/views/purchase/purchaseOrder/index.vue`、`detail.vue`、`shared.ts`（列表/详情共享常量）、`frontend/src/views/baseData/supplier/detail.vue`），可对照参考；**样板不存在或与模板冲突时，以 `references/templates.md` 为准并向用户报告差异**——禁止拿旧版样板推翻模板。
- **回填义务（防漂移）**：本仓库样板页面后续演进时须回填 `references/templates.md` 对应片段；发现脱节，先记 `workflow/papercuts.md` 一行，不当场顺手改。
- **跨分支/跨仓库携带**：复制本文件和 `references/templates.md` 两份。只复制本文件没有施工模板。**权威源 = 本仓库这两份**，携出副本不回流、漂移自负。**本仓库例外**：宿主适配目录（`.trae/`、`.opencode/`、`.codebuddy/`）按仓库纪律只放指针壳，禁放全文副本。
- 本 skill 是**改造模式知识 + 硬约束层**：在本仓库使用时仍走项目工作流（L1 plan → 确认门 → build → UI 实测 → 关单）；其他仓库按「基建依赖与降级表」处理。

## 第 0 步：形态盘点（强制，跳过即违规）

1. 读目标页面 `index.vue` / `detail.vue`（如有）/ Drawer 组件（如有），盘点：
   - **目标形态**（看业务结构，不看当前实现）：实体有明细行/关联单据 → **A 主子表**；实体纯表单无明细 → **B 纯表单**；只读无编辑无详情 → **D 纯查询**。
   - **当前形态**：已有覆盖层详情组件 → 布局重排路径；Drawer 编辑（新建/编辑/查看在 Drawer 里）→ **形态跃迁路径**（见「形态跃迁施工流程」）。
   - **表格技术现状**：目标项目是否已用 AG Grid（查 package.json / 既有页面 import）；未用 → 列入 **S12 一次性接入项**（随本次改造一起做，非可选决策）。
   - **基建现状**：对照「基建依赖与降级表」逐项探测。
2. 产出**改造项清单 + 选型/降级决策 + 存疑点**（如该页无批量操作、明细表是否值得 tab 化）→ AskUserQuestion 让用户确认范围。
3. 用户确认后才立 plan 进入施工。**禁止跳过盘点直接套模板。**

| **A 主子表**（PO 型）       | 实体有明细行（±关联单据） | 直接套 D-1~D-7 全套                                                       | 走「形态跃迁施工流程」→ 新建 detail.vue（A 骨架）+ Drawer 业务迁移下线 |

## 表格技术（列表页，统一 AG Grid）

**效果口径（断言门按此验收）**：
1. 列序 = 定义顺序（复选框 → 序号 → 单号…），视觉顺序零错乱
2. 列宽自适应：主干文本列吃剩余宽度、列头零 `...` 截断；窄列固定宽
3. 行操作 hover 浮层替代固定操作列（省下 280px 级别的操作列宽）
4. 行滚动收在表体内部，外层零滚动条；分页页脚钉底

**选型规则**：
- 目标项目**已用 AG Grid** → 直接按 S5-S8 施工。
- 目标项目**未用 AG Grid** → **直接按 S12 一次性接入**（依赖 + license 注入 + 全局视觉 + 中文 locale + 页面级组件模板全套迁移），随后按 S5-S8 施工。**禁止用 a-table 模拟等效效果**——效果不可达且引入第二套表格口径，属错误路径。

## 形态跃迁施工流程（Drawer 型 → 覆盖层详情，新建/查看/编辑整模块上覆盖层）

跃迁触发：目标页面当前是 Drawer 编辑型，且用户要求的改造范围含新建/查看/编辑（整模块改造默认含）。

1. **读透 Drawer 现状**：表单字段绑定、校验规则、保存流（API 调用与成功后行为）、查看态内容源——跃迁是**搬家不是重写**，业务逻辑逐字迁移。混合形态下「查看态内容源」= index.vue 里既有覆盖层查看态代码（它就是查看态的搬家源，同样读透搬走）。
2. **新建 `detail.vue`**：目标形态 A 用 S1-S4 骨架（上下半区 tab），目标形态 B 用 S9 骨架（表单卡 + sticky footer）+ S11 头部组件；三态入口 `props.mode: 'create' | 'edit' | 'view'`：
   - 编辑/新增态：字段绑定、rules、保存 handler、API import 从 Drawer **逐字搬移**（禁顺手改语义）；提交载荷与原 Drawer 逐字段一致。
   - 查看态：只读栅格（D-2）承载原查看内容；操作按钮进 `#extra`。
3. **列表页挂覆盖层**：`.detail-layer` + Transition（S8 CSS）；原「新增 / 编辑 / 查看」入口全部改为开覆盖层（`detailState = { mode, id }`）。
4. **原 Drawer 下线删除**：同一实体的编辑能力**禁双入口并存**——Drawer 残留会造成两处提交载荷日后漂移（对账死角）；确认无其他引用后整段删除。混合形态下既有查看态覆盖层代码同批下线（查看能力已并入新 detail.vue，禁双详情入口）。
5. **对账红线**：跃迁不改契约——API 契约、查询参数、提交载荷逐字段不变；保存成功后的列表刷新与关闭行为对齐既有口径；资格判据三处同源口径不变。

## antd 陷阱清单（施工前必读，每条均已实证）

| #   | 陷阱                                                                                                                 | 解法（见 S 片段）                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| T1  | a-spin 根实为 `.ant-spin-nested-loading`，组件上的自定义 class **不落根**——按类选择全链失效、整区塌 0                | 按 antd 结构类选择（S1）                                                               |
| T2  | `.ant-tabs-extra-content` 默认非 flex，块级按钮组把最大化按钮挤到第二行                                              | `#rightExtra` 里自带 `.tab-extra-row` flex 容器（S1/S4）                               |
| T3  | tabs 内容区默认非 flex，链断一层整区塌 0                                                                             | `.ant-tabs / content-holder / content / tabpane-active` 逐层 `min-height:0`（S1）      |
| T4  | 容器高度不定（可撑开）时子项百分比 min-height/height 解析失效                                                        | ResizeObserver 注入 `--layer-h` 变量，绝对像素计算（S2）                               |
| T5  | a-table 内部另有一层 spin（wrapper > spin > container > table），漏一层 `.ant-table` 的 flex:1 就失效、表体压成 0 高 | 表内滚动链把 `.ant-table-wrapper` 与两层 spin 全补进（S1）                           |
| T6  | antd 纯横向滚动会内联 `overflow-y:hidden`，表体纵滚失效                                                              | `.ant-table-content` 上 `overflow-y:auto !important`（S1）                             |
| T7  | `a-row :gutter` 负外边距（每侧 -4px）撑出面板横向空白                                                                | 上半区容器显式 `overflow:hidden`（S1）                                                 |
| T8  | antd 小屏（<576px）让 label 撑满整行变竖排                                                                           | label 强制横排口径 `width/flex/padding !important`（S1）                               |
| T9  | a-tag 胶囊被「基准归零拉满」铺满整列变整列色块                                                                       | 拉满选择器 `:not(.ant-tag)` 排除（S1）                                                 |
| T10 | AG Grid `rowMouseEnter` 回调实测不触发（真实/synthetic 鼠标均无）                                                    | DOM 事件委托 mouseover/mouseout（S6）                                               |
| T11 | AG Grid pinned-left 容器渲染在最前，把中间列或操作列 pin 到左侧会打乱「复选框→序号→单号」视觉顺序                     | 只左固定定义顺序上的连续前导列；多选列走 selectionColumnDef；其余不 pin（S7）          |
| T12 | Chrome 对浮层移出 DOM 后露出的行补发 mouseover，进详情后浮层重建遮挡                                                 | 浮层显示入口处详情层打开即熔断（S6）                                                   |
| T13 | 浮层不在滚动视口内、卡片 overflow:hidden，滚轮落空                                                                   | 浮层 wheel 手动转发 `.ag-body-viewport`（S6）                                          |
| T14 | 全局样式 `.ant-card-body` 带 `!important` 内边距，页脚钉底失效                                                       | 高特异性 `padding:0 !important` 覆盖（S8）                                             |
| T15 | Vue reactive Proxy 干扰 AG Grid 内部状态                                                                             | gridOptions 用普通对象（S7）                                                            |
| T16 | 详情页明细 a-table 不设 `:scroll.y` 时表体默认不纵滚，「表内滚动」静默失效                                           | CSS 强制链 `.ant-table-content { overflow-y:auto !important }`（S1）                  |

## 硬红线（禁改清单，违反即返工）

1. **不动覆盖层机制**：`.detail-layer` 的 `position:absolute; inset:0; overflow-y:auto` 与「列表实例保持存活」口径逐字保留。
2. **契约零改动**：API 契约、查询参数、提交载荷逐字段不变（形态跃迁 = 搬家不重写，迁移前后提交载荷逐字段对账）；行内按钮/批量资格/复选框可选三处同源同步；后端错误消息原样展示。
3. **禁双编辑入口**：跃迁完成后原 Drawer 必须下线删除——同实体编辑能力双入口并存会造成提交载荷日后漂移（对账死角）。
4. **两态同链必测**：查看态与编辑/新增态共用高度链时，**两态都必须实测**，只测一态不算过。
5. **最小改动**：只动目标模块文件 + 共享组件插槽级增量；禁顺手重构、禁格式化无关代码、禁修无关 Lint 警告；模板搬移时 handler 逐字不动。
6. **机制注释同步**：改布局须同步更新文件内既有机制注释（高度模型/链路注释），防注释与代码脱节；本文片段内机制注释落地时逐字保留。
7. **提示与列表态**：目标仓库若有统一提示守卫 / URL 态管理等基建则一律走基建（如本仓库 `utils/notify.ts` / `utils/listUrlQuery.ts`），禁绕过。

## 验证门（全套断言实测，缺项不算过）

**详情页（目标形态 A，D-1~D-7 全改时）**
