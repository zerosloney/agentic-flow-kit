# perf — 性能排查

## 触发

- 用户报「慢 / 卡 / 加载久 / 接口 N 秒」。
- 方案含性能取舍，需要用实测定夺。

## 0. 先定义可测目标

指标（LCP / 接口 p95 / 列表首屏 / 构建耗时）+ 场景（页面 / 接口 / 数据量）+ 达标线。说不清指标 → 先测量再谈优化，禁凭感觉改。

## 1. 基线（同机 / 同数据 / 同并发）

- 复跑 $\ge 3$ 次，取中位与最慢；记录机器负载与数据量。
- 证据落 `tmp/perf/<topic>-baseline.json`（或 stdout 存档）。

## 2. 定位

- 前端：Performance trace / LCP / 长任务；后端：慢查询、N+1、无界取数（性能三项见 `.agents/skills/review-method/SKILL.md`）。
- 一次只验证一个假设；假设被证伪就写下结论再换。

## 3. 单变量改动

一次只改一处；不改口径、不换数据、不调机器。门禁耗时类改动区分「门变快」与「质量提升」。

## 4. 复测与接受

- 同场景复跑 $\ge 3$ 次；改善必须超过噪声带（数字可信性单源 `.agents/skills/number-vetting/SKILL.md`）。
- 未过噪声带 → 回滚或记「未证实」，不写进结论。

## 5. 落账

表格：基线 / 改动 / 复测 / 结论 + 证据路径。环境抖动（共享库锁、机器负载）先隔离复跑，按 `review-method/golden-set.md` #21 口径归属，不误报回归。

## 红线

- 不同时改两个变量；不用单次运行；不优化没有测量的部分。
