# arena — 并行对比选型

## 触发

- 设计分叉没有先例，两个以上方案都说得通。
- 用户说「对比一下 / 各做一个看看 / 选型」。
- 方案会锁定后续实现形状，选错返工成本高。

## 核心

**同一 brief，独立臂，裁判选底座 + 嫁接。** 不是并行实现同一个文件；是并行**提案**，再选一个底座。臂之间不共享上下文（防锚定）。

## 步骤

1. **固定 brief**：目标、约束、验收判据、非目标、证据要求。每个臂拿到**逐字相同**的 brief。
2. **选臂**：2–3 个，差异轴要真实——不同模型 / 不同架构 / 不同数据形状。不要跑 N 个同构臂。
3. **并行派发**：一个 `task` 批次；每个臂返回：方案、取舍、风险、最小证明（能跑的原型/测试/伪代码）。
4. **裁判**：按验收判据逐项打分；选**一个底座**；列出从其他臂**嫁接**的具体部分；被拒方案写一句为什么。
5. **落地**：实现底座 + 嫁接；对选定设计跑 `.agents/skills/blast-radius/SKILL.md`；再 `verify --scope`。
6. **落账**：`workflow/delegations.md` 每个臂一行 + 裁判结论；长跑加 `decisions.tsv` 一行。

## 输出

| 臂 | 方案 | 强项 | 风险 | 最小证明 | 结论 |
|---|---|---|---|---|---|
| A | … | … | … | … | 底座 / 嫁接 X / 拒 |
| B | … | … | … | … | … |

- **底座**：选谁、为什么。
- **嫁接**：从其他臂拿哪几块、怎么合。
- **拒绝**：每个被拒方案一句理由。
- **未决**：需要 owner 拍板的产品/偏好判断。

## 本仓落点

- 派发：`task` 的 `tasks[]` 批次；`model-roles.json` 的 `judgment` 角色。
- 复核：选定设计后按 `.agents/skills/interrogate/SKILL.md` 多镜拆。
- 证明：`.agents/skills/blast-radius/SKILL.md`（安全因为 X 要跑代码）。
- 落账：`workflow/delegations.md`；聚合 `node .agents/scripts/agg-delegations.mjs`。

## 边界

- 臂之间不共享结论；共享 brief 即可。
- 不把 N 个方案全合进去——选一个底座，嫁接要具体到文件/函数。
- 耦合实现（同一文件/同一契约）不用 arena，用串行。
