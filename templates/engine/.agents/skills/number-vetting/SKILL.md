# number-vetting — 数字体检（五问）

任何数字进 `workflow/metrics.md`、`verifications.jsonl` 解读、PR 正文或方案结论前，逐问过一遍。任一问答不上 → 标「存疑」，不得作为决策依据。

## 五问

| # | 问 | 不合格信号 |
|---|---|---|
| 1 | **限制因素**：这个数被什么卡住？ | 说不清瓶颈；把串行等待算进单项耗时 |
| 2 | **调参/环境**：热缓存、并行度、机器负载造成的？ | 冷/热跑混算；换机器不复现 |
| 3 | **误差/噪声**：方差多大？复跑分布？ | 单次样本；差值与噪声同量级 |
| 4 | **口径/窗口**：样本 n、时间窗、排除项与上次一致？ | 口径悄悄换了；跨模型代际直接比 |
| 5 | **端到端相关性**：测的是用户感知的那段？ | 微基准涨了，端到端没动 |

## 判定与落账

- 三档：**可信**（五问全过）/ **存疑**（缺 1–2 项，补测后复核）/ **不可用**（限制因素不明或口径漂移）。
- 落账格式：`值（样本 n / 窗口 / 口径 / 复跑 k 次）`；缺项写「未测」，不写 0。
- `{{指标名}}` 签名由取数器填实时值（check16），不手填。

## 本仓既有口径（先读，别另立）

- 峰值 % 的读法：`workflow/metrics.md` 文首「数字体检」注——静息态 ≈93% 是构造使然，判压力看回填速率，不看峰值。
- 跨模型代际比较：先读 `workflow/delegations.md`「模型代际基线」；旧月快照不重算。
- 门禁耗时：用 `verifications.jsonl` 的 `wallMs`；2026-10-16 前绿行无该键、回退各门之和，两种口径不混比。

## 红线

- 不把「门禁变快」写成「质量提升」。
- 不用单次运行证明性能；不用均值掩盖长尾（最慢门单列）。
