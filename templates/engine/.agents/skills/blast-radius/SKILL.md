# blast-radius — 影响面证明

## 触发

- 用户问「这改动还会碰坏什么 / blast radius / 有没有漏」。
- diff 很小但跨了函数边界、共享状态、序列化格式、DB 列、feature flag。
- 复核时对「应该没事」不放心，需要可复核的证据。

## 核心

**不要相信自己的书面分析。** 影响面说明读起来总是像对的，无论真假。找出整个判断依赖的**一个或两个事实**，用跑代码证明它们；证明不了就写 `unproven`。

列调用者不是本事——grep 一秒就能列。本事在 grep 停下来的地方：库源码、固定版本、运行时顺序、wire format、DB 列、另一门语言读同一份字节、三跳之后的下游。

## 确定性阶梯（每个事实标停在哪一级）

1. **我说是**——单独不算证据。
2. **指到行**——真实 `file:line`，或库自己的源码。
3. **反例走不通**——把失败路径一步步走完，确认到不了。
4. **跑过**——一个小脚本/测试调用真实代码，错了就大声失败。
5. **在运行的应用里复现**——端到端证据。

第 4 级通常就是一个小脚本：import 应用同一份库，调用你担心的那个函数，断言结果。

## 步骤

1. **读改动**：diff、新增/修改/删除的符号、行为差异（包括 diff 没写出来的部分）。用 `git log -S`、`xd://lsp` references、`kb-search` 补上下文。
2. **找那一个安全事实**：多数看起来危险的改动，安全只因为一个事实（例：「这个调用只丢已死的缓存项，别的什么都不做」）。把时间花在这里，不要列一长串 maybe。
3. **看 grep 停下的地方**：库源码与固定版本、本地 patch、微任务/卸载/teardown 顺序、API 返回的 JSON、DB 列、wire format、另一门语言、feature flag、三跳下游。
4. **诚实列风险**：每条给发生概率与代价、`file:line`、怎么查；确认的清单独列。搜不到也是答案，不要编调用者或 API。
5. **证明那一个事实**：写脚本/测试跑真实代码，贴输出。证明不了 → `unproven`。
6. **大/宽改动**：让多个模型独立回答同一问题，再合并——不同模型抓不同的真 bug。

## 输出格式

- **改了什么**：包括不明显的部分。
- **安全因为**：那一个事实 + 停在第几级 + 证明输出；证明不了写 `unproven`。
- **风险**：每条 = 怎么坏 + `file:line` + 概率/代价 + 怎么查；重要的贴证明。
- **已排除**：查过且为什么没事。
- **合入前**：最便宜的、能抓住真 bug 的测试/复现（含你写的脚本）。

## 本仓落点

- 复核：`.agents/commands/review.md` P1「影响面证明」。
- 设计：`.agents/commands/stages.md` Design 章契约面变更。
- 机器面：`verify-scope.mjs` 只算 diff 面；本技能补「为什么安全」。
- 证据：证明脚本放 `tmp/` 或随 PR 提交；不要只写结论。
- 边界：本技能不替代 `verify` 门禁；它证明的是「没碰坏别处」，不是「本次改动正确」。
