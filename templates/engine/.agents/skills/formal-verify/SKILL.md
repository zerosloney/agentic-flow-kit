# formal-verify — 形式化验证资产（可选，advisory）

思想来源：pstack `create-formal-verification-skill` / `maintain-formal-verification-skill`（本仓改写并 advisory 化：不进门禁面）。

## 触发

- 用户要求：`形式化验证` / `不变式` / `模型检查` / `性质测试` / `状态机建模`。
- 任务触达状态机、并发、一致性高危面（设计 / 评审 / 排障）：先过「适用面判定」3 类线索，命中 ≥1 条才开工。

## 定位与边界

- advisory 面：资产与核对结果只供参考，不进 CI、不接 pipeline、不做任何提交门；不登记 `.agents/config/mechanism-registry.md`（未进门禁面，无一进一出）。
- 「设计是否正确」的结论由人下：模型检查与性质测试的输出原文即证据，本技能不代下结论、不把红绿解读成「安全印章」。
- 资产红 ≠ 阻断：处置三选一（修设计 / 修资产 / 记豁免并写理由）由人裁决；豁免条目须写复核判据与有效期。

## 适用面判定（先判再动）

逐条核对，命中任一线索才算适用；全不命中 → 走 loud-skip：

- 状态机工件：显式状态枚举 + 迁移逻辑（工作流 stage 表、订单流转、协议握手）；核对线索：集中状态定义文件、`state` / `stage` 迁移分支。
- 锁 / 事务 / 并发面：互斥锁、事务边界、幂等键、租约续期、单写者约束；核对线索：`lock` / `transaction` / `lease` / `acquire` / `idempotent` 命中面。
- 分布式一致性面：共识、副本同步、补偿回滚、重试投递（`at-least-once` + 幂等消费）；核对线索：重试与补偿路径、跨服务事件序。
- 判定留痕：命中的线索 + 证据路径（file:line）写进资产清单头部；该判定是 SKIP 或开工的唯一依据。

## 资产创建（首次开工时）

1. 不变式清单 `.agents/formal/invariants.md`：逐条编号 FV-1 起，含「描述 + 适用工件 + 可核对判据」；写不出可核对表达式的条目降级为普通测试需求，不进清单。
2. 状态机模型 `.agents/formal/<name>.md`：状态集 / 迁移表 / 终态 / 不变式引用（FV-x）；每个迁移至少 1 条性质用例，可达性、无死锁、不变式保持三类至少各 1。
3. 接入方式按「工具无关 + 按栈举例」写进模型文件头部：模型检查器吃显式迁移表，性质测试吃运行时断言。举例（非门禁，任选或不用）：dotnet / Java 用 `TLA+` 建模迁移表；TS / Node 用 `fast-check` 性质测试；Rust 用 `proptest` / `Kani`；Go 用 `go test` + property 断言。
4. 每份资产头部登记维护腿锚点：高危面代码路径清单（与适用面判定的证据路径一致），漂移核对以此为界。

## 维护腿（改动时）

- 改动触达资产登记的高危面路径 → 复核：迁移表对当前代码逐条核对、性质测试全跑一遍，改动留痕记一行 `FV 复核: <资产名> <pass|fail>`。
- 代码出现资产未覆盖的状态 / 迁移 / 锁面 → 在 `.agents/formal/invariants.md` 追加「漂移候选」条目（路径 + 一句话差异）；只出候选不改模型正文，补模型还是收窄适用面由人裁决。
- 纯文档 / 纯样式改动、未触高危面路径 → 不触发本腿（0 条复核记录要求）。

## loud-skip 纪律

命中任一条 → 输出一行 SKIP（写明命中的条款）并 exit 0；不判红、不造数、不建空资产：

- 适用面判定 3 类线索全未命中（项目无状态机 / 并发 / 一致性高危面）。
- 选定的验证工具不可用（未安装或不可执行，探测退出码非 0）且本轮无既有性质测试可跑。
- `.agents/formal/` 资产不存在且本轮触达的高危面尚未建资产：SKIP 并给建资产的下一步。
- SKIP 输出样例：`SKIP formal-verify: 无高危面命中（适用面判定逐条未命中，exit 0）`。
