# 量化断言「指标签名」单源登记表（check-loop 检查 16 共读）
#
# 背景（2026-09-28 claim-exceeds-fix）：结论文档里跨文档引用的量化值若各自手写，
# 极易在事实变更后不同步——本仓已实证：同一指标在一处改了、另一处没改，
# 而「五处文件同步」这句话本身无人核对（该单真正被门禁抓住的方式，是事后人工复核）。
# 本表把「哪个指标、当前取值多少」收敛为单源，供 check-loop 检查 16 对账。
#
# 用法：活跃态文档（draft/approved/open）引用某个已登记指标时，按**签名形态**书写，
# 检查 16 会实时取数比对。签名形态：\{\{指标名\}\}（双花括号包裹指标名，小写点分）。
#   例（下面是「讲语法」，故加反斜杠转义；**写真断言时不加反斜杠**）：
#     本仓台账共 \{\{ledger.lines\}\} 行，其中无 batch 字段 \{\{ledger.linesWithoutBatch\}\} 行。
# 写作时**不要手写数字**——写完跑 check-loop，工具会把实时值填进提示里供你替换。
# 转义按「逐个出现」生效：同一行里 \{\{x\}\} 是示意、\{\{y\}\} 是真断言时，只豁免前者。
# （本例的指标名曾写成 ledger.total / ledger.noBatch 两个**并不存在**的名字——本表不被
#   检查 16 扫描（它是 .txt 非 .md），故这类笔误不会被自动抓到，只能靠复核。已据实更正。）
#
# 为什么用显式签名而非全文数字扫描（据实说明，非偷懒）：
#   本仓活跃文档中「N 行 / N 条 / N 份」类表述有 49 处（实测：活跃态 21 份文档逐行计），绝大多数是**历史叙述**
#   （描述某次提交当时的规模，天然不会随当前事实变化）。全文扫描会对这些正确的
#   历史叙述产生大量假阳性——而 check-loop.mjs 已把「无判定依据的行不产出不可
#   消除噪声」立为红线（沿 2026-09-27 audit-gate-hardening P3 教训：噪声淹没真漏点）。
#   故本检查**只校验显式声明的签名**：假阳性恒为 0，代价是覆盖面依赖作者登记。
#
# 格式：每行 `<指标名> = <取数表达式>`；`#` 开头为注释；空行忽略。
# 取数表达式（闭集，全部本地确定性、零网络）：
#   ledger.lines          台账 .agents/confirmations.jsonl 的非空行数
#   ledger.linesWithoutBatch   台账中不含 "batch" 字段的行数（schema 演进前历史行）
#   ledger.linesWithBatch      台账中含 "batch" 字段的行数
#   docs.count.<sub>      workflow/<sub> 下文档份数——**与文档扫描同口径**：以数字开头的
#                         .md、排除 _TEMPLATE.md、且仓库模式下只计 HEAD 已跟踪件
#                         （故并行会话的未跟踪新档不计入）；sub ∈ intents/specs/plans/incidents
#   docs.count.all        上述四类合计
# ── 新增指标（2026-09-28 adopter-derivers 起）────────────────────────────────
# 分两层取数，**内置优先**：
#   ① 引擎内置 8 个指标（下表）——装户零配置即用，不需要做任何事。
#   ② 项目自有指标——写 `.agents/metric-derivers.mjs`（**owned**，sync 永不覆盖），
#      导出 `derivers` 对象（指标名 → 取数函数），并在此表加同名一行。
#      **后缀必须是 `.mjs`**（引擎只认这一个路径；写 `.cjs` 会被当作不存在，
#      且 `.cjs` 不归 owned——若被误用会重演「登记表 owned 配引擎 managed」那类缺陷）。
#
# 示例 `.agents/metric-derivers.mjs`：
#     export const derivers = {
#       'my.migrations': (ctx) => ctx.glob('backend/migrations/*.sql').length,
#       'my.apiCount':   (ctx) => ctx.countFiles('src/api', (f) => f.endsWith('.controller.ts')),
#     };
# ctx 提供（同步，免你重复造轮子；其余请自行 `import fs from 'node:fs'`）：
#     ctx.root                    仓库根绝对路径
#     ctx.read(rel)               读文本文件（LF 归一），不存在返回 ''
#     ctx.glob(pattern)           极简 glob（* / **），返回相对路径数组
#     ctx.countFiles(dir, pred)   递归计数（可传谓词）
#
# 三条硬约定（违反即 fail-loud）：
#   1. **必须是同步函数**（返回 number，不得 async/Promise）——本检查零网络、要求本地确定性
#   2. 必须**确定性**：不得依赖网络、不得依赖当前时间
#   3. 返回值须为**有限数字**（Number.isFinite）
#
# 失败语义（**绝不静默降级**）：模块语法错 / 抛异常 / 未导出 derivers / 返回值非法
#   → 一律出 `[WARN 装户取数器载入失败]` 或 `[WARN 指标取数失败]`，**不会**退化成
#   「只用内置指标」——否则你会误以为「忘了登记」而查不到真因。
# 指标名与内置同名时：**内置优先**，你的定义被忽略（会出 advisory 明示）。
#
# 注：本检查**不设取数超时**——请让取数器保持轻量（秒级）。死循环会拖慢门禁。
# 另：装户模块的「取数器」在引擎侧（check-loop.mjs，managed）；本表与 derivers.mjs 同归 owned。
#
# 注意：不登记 advisory 总数类指标——它由 check-loop 自身产出（检查 16 是其一部分），
# 自引用会让「报告本身改变被报告的数」，产生不可稳定对账的循环。
